## 参考项目

| 项目 | 已核对的做法 | PixelPet 可借鉴的部分 |
|---|---|---|
| [LorisYounger/VPet](https://github.com/LorisYounger/VPet) | WPF 桌宠；互动、投喂、较多动画与状态、创意工坊；核心与桌面功能分开 | 为动作增加进入/持续/退出阶段，建立情绪和精力驱动的行为调度，避免随意打断互动 |
| [ayangweb/BongoCat](https://github.com/ayangweb/BongoCat) | 按键、鼠标及手柄输入触发动作；支持自定义 Live2D 模型；离线运行 | 让用户操作与反应有清晰对应，先做好轻量、可关闭的即时反馈，保留离线默认行为 |
| [duzexu/desktop-pet](https://github.com/duzexu/desktop-pet) | Electron 客户端；素材包导入/导出、优先级和冷却时间、控制面板、番茄钟及定时互动 | 将人物资源与程序分开；引入有版本号的 manifest、规则配置、冷却时间和集中设置面板 |

[desktop-pet 的素材包文档](https://github.com/duzexu/desktop-pet/blob/master/docs/USER_GUIDE.md) 进一步说明了包结构、动画片段与规则的关系，可作为资源格式设计参考。以上项目各自有不同的代码与素材许可；本轮只参考设计，不将它们的许可套用到本项目。

## 当前最值得解决的问题

当前 36 张 GPT 帧是六组关键姿态，能够表现肢体动作，但还不等于完整流畅动画。镜框、脸型、服装边线和裤子小图案会变化；动作之间经常直接跳回站姿；统一包围盒对齐也不能替代正确的身体锚点。

因此应先改善角色与动画质量，而不是先增加大量动作或立刻换引擎。继续保持 Python + Win32；资源、行为与平台服务按实际需求逐步拆分。

## 优先级与验收

| 优先级 | 开发内容 | 具体实现方向 | 完成标准 |
|---|---|---|---|
| P0 | 一致性修整 | 固定头部和眼镜参考；逐帧比较脸、刘海、镜框与服装细节；针对问题帧重新生成 | 原图与所有关键帧并排仍是同一人物，播放时不会频繁换脸或闪动衣服 |
| P0 | 动作衔接 | 每个动作支持 enter/loop/exit；补绘站起、坐下、起步和停步；增加手动脚底/身体锚点 | 睡觉唤醒和走停不再直接切换成另一张姿势图 |
| P0 | 走路周期 | 明确左右脚和前后遮挡，补足约 8–12 个经过评审的姿态；根据步幅匹配位移 | 左右脚确实交替承重，脚离地明确，行走不滑动 |
| P1 | 设置面板 | 基于已有 tkinter 或 Win32 独立窗口，管理大小、散步、气泡频率、静音和启动项 | 用户不用编辑 JSON 就能完成日常配置 |
| P1 | 行为调度 | 拖动/点击/主动行为/散步/待机分优先级；引入冷却、状态锁和完成回调 | 拖动或互动不会被随机行为打断，睡觉不会反复坐下站起 |
| P1 | 轻量陪伴 | 番茄钟、休息提醒、专注时减少走动和气泡 | 能离线完成一次专注与休息流程，不打断用户输入 |
| P2 | 精力与心情 | 少量状态值影响行为频率和表情，不用高频打扰制造养成压力 | 长期运行能表现状态变化，关闭程序后可恢复 |
| P2 | 角色包 | 版本化 manifest，声明帧序列、时长、锚点、命中区域和行为；包内只允许数据 | 可导入第二个人物而无需改程序，不执行包内任意脚本 |
| P2 | 输入反馈 | 可选的鼠标靠近、悬停或键盘节奏反应，配置开关及频率上限 | 反馈轻量明确，默认不记录用户输入内容 |
| P3 | 可选聊天 | 明确的启用入口、本地保存设置、联网状态提示、失败回退离线文案 | 网络失败时宠物仍可使用，模型调用不阻塞窗口线程 |
| 持续 | 发行质量 | 不同 DPI 多屏、缩放/热插拔、休眠恢复、持久化、自动构建与签名规划 | 发布前有稳定回归流程及可复现构建记录 |

这些条目是后续计划，并未作为本轮已完成能力。Live2D/骨骼动画可以在高质量分层素材准备好后评估；单张参考图不能直接提供完整绑定模型。

## 推荐下一轮交付

先完成一个“扶眼镜 → 开心回应 → 回到待机”的完整互动，以及“坐下 → 闭眼循环 → 站起”的睡眠过渡。每个动作包含关键姿态、适当中间帧、逐帧时长、脚底/头部锚点、深浅背景预览，再接入行为调度。用少量完整动作建立质量标准后，再扩展动作库。
